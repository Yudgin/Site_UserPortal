# План интеграции мессенджеров (Viber / Telegram / WhatsApp)

Документ для владельца сервисного центра RunFerry. Цель — принимать заявки клиентов из Viber, Telegram и WhatsApp в один общий инбокс на сайте/портале, автоматически привязывать переписку к клиенту и к его ремонту, и по возможности отвечать автоматически (ИИ/шаблоны).

Главная развилка, которую нужно понять сразу: у каждого мессенджера есть **простой ручной режим** (приложение на телефоне владельца, встроенные автоответы, бесплатно) и **режим API/бот** (входящие приходят на ваш сервер через webhook, можно автоматизировать и интегрировать с порталом). Для «единого инбокса на сайте» нужен именно режим API/бот. Ручной режим используется как «мостик»: автоответ со ссылкой ведёт клиента в бота.

## 1. Что подготовить владельцу (по каждому мессенджеру)

### 1.1. Viber

В Viber два разных продукта — их часто путают:

- **Вариант A — бесплатный Business Account (бизнес-профиль).** Создаётся прямо в приложении Viber на телефоне владельца, без разработчиков и партнёров. Ручная переписка, каталог до 50 услуг, встроенные автоответы. Webhook и программной отправки НЕТ.
- **Вариант B — Viber Chatbot (Bot API).** Нужен для webhook, автоответов через ИИ и интеграции с порталом. С 05.02.2024 бота **нельзя завести самому** — только по заявке на коммерческих условиях (EUR 100/мес), напрямую в Rakuten Viber или через официального партнёра (Infobip, TurboSMS, Messaggio, Smart Sender и др.).

Рекомендация: начать с бесплатного бизнес-профиля (A), а платного бота (B) заводить только когда действительно понадобится серверная автоматизация.

**Чеклист подготовки (Viber):**

- [ ] Смартфон (iOS/Android) с установленным Viber и активным номером компании/владельца — на нём будет админ-доступ и появится токен бота.
- [ ] Название, логотип (картинка), категория бизнеса, описание сервиса, часы работы, адрес, ссылка на сайт/лендинг, контакты — для заполнения бизнес-профиля.
- [ ] Готовые тексты автоответов: приветствие (welcome) и сообщение вне рабочих часов (away); при желании — со ссылкой на сайт и/или диплинком `viber://pa?chatURI=имя_бота`.
- [ ] (Для бесплатного профиля) Платить не нужно; при желании — заявка на верификацию (синяя галочка), проходит ручную модерацию Viber.
- [ ] (Только для чат-бота, Вариант B) Заявка в Rakuten Viber напрямую ИЛИ через официального партнёра/CPaaS в Украине.
- [ ] (Только для чат-бота) Подписанный договор + согласие с Terms & Conditions, готовность платить EUR 100/мес за бота + оплату исходящих сообщений.
- [ ] (Только для чат-бота) Реквизиты/данные компании для договора с партнёром и оплаты.
- [ ] (Только для чат-бота) Публичный сервер с HTTPS и валидным SSL-сертификатом от доверенного CA, эндпоинт `/viber/webhook` отвечает HTTP 200.
- [ ] (Только для чат-бота) После создания бота — забрать токен: More → Settings → Bots → Edit Info → Your app key; передать разработчику для `X-Viber-Auth-Token`.
- [ ] (Рекомендуется) Заранее подготовить имя бота (chatURI) для диплинков.

### 1.2. Telegram

Всё бесплатно. Бот создаётся владельцем самостоятельно через `@BotFather` — юрлицо, документы и верификация не нужны.

**Чеклист подготовки (Telegram):**

- [ ] Личный Telegram-аккаунт владельца (действующий номер телефона) — на нём создаётся бот и, при желании, включается Telegram Business.
- [ ] Создать бота через `@BotFather` (`/newbot`): придумать display name и уникальный username, заканчивающийся на `bot` → получить ссылку `t.me/xxx_bot`.
- [ ] Сохранить HTTP API токен бота в безопасном месте (в нашем проекте — env/Secret Manager, не хардкодить).
- [ ] Публичный HTTPS-домен/эндпоинт для webhook: TLS 1.2+, валидный сертификат, порт 443/80/88/8443.
- [ ] Придумать и сохранить `secret_token` для проверки заголовка `X-Telegram-Bot-Api-Secret-Token` на webhook.
- [ ] Оформить бота в BotFather: аватар (`/setuserpic`), описание (`/setdescription`), about (`/setabouttext`), команды меню (`/setcommands`).
- [ ] (Опционально, для авто-ответов на личном номере) Оформить Telegram Premium на аккаунт владельца и включить Telegram Business.
- [ ] (Опционально) Настроить greeting / away / quick replies со ссылкой `t.me/xxx_bot`.
- [ ] Разместить ссылку `t.me/xxx_bot` на сайте/в презентации, чтобы клиент сам нажал Start (бот не пишет первым).

### 1.3. WhatsApp

Два разных продукта — не путать:

- **WhatsApp Business App** (обычное приложение из сторов) — ручные чаты + простые автоответы. Webhook и интеграции с порталом НЕТ. Для агрегатора не подходит.
- **WhatsApp Business Platform (Cloud API)** — то, что нужно для интеграции. Хостится у Meta. Требует верификации бизнеса.

Критично: **на одном номере два продукта одновременно не живут.** Как только номер зарегистрирован в Cloud API, обычное приложение с ним перестаёт работать. Если владелец хочет и ручной автоответчик App, и Cloud API — нужны **два разных номера**.

**Чеклист подготовки (WhatsApp Cloud API):**

- [ ] Выделенный номер телефона ТОЛЬКО под Cloud API — чистый, НЕ зарегистрированный сейчас ни в обычном WhatsApp, ни в WhatsApp Business App (если занят — сначала удалить с него аккаунт WhatsApp). Мобильный или стационарный, главное — принять код по SMS/звонку.
- [ ] Доступ к этому номеру в момент регистрации (принять OTP-код).
- [ ] Facebook-аккаунт с правами администратора к Meta Business Portfolio (`business.facebook.com`).
- [ ] Документы для Business Verification: свидетельство ФОП/выписка ЕГР для ООО, подтверждение адреса бизнеса, желательно рабочая почта на домене сайта и сам сайт (портал есть — это плюс).
- [ ] Определиться с Display Name — реальное название сервиса, готовое пройти модерацию Meta.
- [ ] Придумать и записать 2-step verification PIN (6 цифр) для номера — обязателен при регистрации.
- [ ] Настроить HTTPS-endpoint под webhook (валидный TLS обязателен) + придумать Verify Token.
- [ ] Получить App Secret приложения (для проверки подписи `X-Hub-Signature-256`).
- [ ] Создать System User и сгенерировать постоянный access token с правами `business_management`, `whatsapp_business_messaging`, `whatsapp_business_management`.
- [ ] Привязать способ оплаты (карту) к WABA для биллинга платных шаблонов.
- [ ] Решить, нужен ли ОТДЕЛЬНЫЙ второй номер, если параллельно нужен обычный WhatsApp Business App с автоответчиком.

## 2. Автоответчик → бот (воронка)

Идея одна для всех трёх мессенджеров: клиент пишет на «человеческий» аккаунт → срабатывает встроенный автоответ → в тексте автоответа даём ссылку на бота/сервис → клиент переходит и попадает в автоматизированный поток, где работает webhook и ИИ. Это обходит главное ограничение всех трёх платформ — **бот не может написать клиенту первым «в холодную».**

### 2.1. Viber

Автоответы работают в обоих вариантах:

- **Бесплатный профиль (A):** Business Settings → Automated Responses. Доступны:
  - **Welcome message** — при первом открытии/сообщении в чат.
  - **Away message** — сначала задать Business hours, затем включить «Send away message» (опции: только вне рабочих часов / всегда).
  - **Quick Replies** — быстрые ответы на частые вопросы.
- **Чат-бот (B):** приветствие реализуется программно и **бесплатно** — при открытии чата боту приходит callback `conversation_started`, и бот вправе отправить одно welcome-сообщение (в течение ~5 минут). Оно не тарифицируется.

Ссылку вставить можно: обычный `https://`-линк на сайт и/или Viber-диплинк на бота `viber://pa?chatURI=имя_бота`. Полный формат диплинка: `viber://pa?chatURI=<имя_бота>&context=<контекст>&text=<предзаполненный_текст>` (`text` подставляется в поле ввода клиента, `context` виден боту при старте).

Нюанс: `viber://`-диплинки надёжно срабатывают **внутри** Viber; во внешних браузерах могут не открыться. Поэтому в тексте автоответа давайте и обычный `https`-линк на сайт, и (при желании) диплинк.

**Пример текста автоответа (Viber):**
> Вітаємо у сервісі RunFerry! Щоб оформити заявку на ремонт, напишіть нашому боту: viber://pa?chatURI=runferry_bot або перейдіть на сайт https://runferry.de. Ми на зв'язку в робочі години.

### 2.2. Telegram

Авто-ответы есть через **Telegram Business** (не через бота) и только при активной подписке **Telegram Premium** (Business-функции входят в Premium без доплаты). Настройка: Settings → Telegram Business.

- **Greeting message** — автоматически новому пользователю (или после периода тишины).
- **Away message** — вне рабочих часов / в отпуске.
- **Quick replies** — шаблоны по вводу `/`; официально поддерживают ссылки, медиа, файлы.
- **Chatbot** — можно подключить своего бота к бизнес-аккаунту и ограничить, какие чаты он видит.

Ссылку `t.me/xxx_bot` безопаснее всего вставлять в **quick replies** (документация гарантирует поддержку ссылок). В greeting/away текст с URL Telegram тоже делает кликабельным.

Практический сценарий: greeting/away на личном аккаунте владельца → ссылка `t.me/xxx_bot` → клиент попадает в бота, где работает webhook и вся автоматизация.

**Пример текста автоответа (Telegram):**
> Вітаємо! Оформити ремонт і стежити за статусом зручно в нашому боті: t.me/runferry_service_bot — натисніть Start. Сайт: https://runferry.de

### 2.3. WhatsApp

Встроенный автоответчик есть только в **WhatsApp Business App** (не в Cloud API):

- **Greeting message** — при первом сообщении клиента или после 14 дней тишины. Settings → Business Tools → Greeting message.
- **Away message** — вне рабочих часов / когда не отвечаете. Расписание: Always send / Custom schedule / Outside business hours; можно выбрать получателей.
- **Quick replies** — до 50 заготовок, но агент вставляет их вручную.

Ссылку в текст greeting/away вставить можно — WhatsApp делает полный `https://`-URL кликабельным (отдельной «кнопки» в приложении нет).

В **Cloud API** «автоответчик» — это ваш код: приходит webhook о входящем → backend сам отправляет ответ (внутри 24-часового окна — свободный текст; вне окна — только одобренный шаблон). Приветствие/away = ваша серверная логика.

Важно по стратегии: автоответчик из App и интеграция через Cloud API **не могут работать на одном номере одновременно**. Либо App (ручные автоответы + ссылка), либо Cloud API (авто-ответы кодом) — на разных номерах, если нужно и то и другое.

**Пример текста автоответа (WhatsApp Business App):**
> Вітаємо у RunFerry! Щоб оформити заявку на ремонт, напишіть нашому боту або перейдіть за посиланням: https://runferry.de/chat. Відповімо в робочі години.

### 2.4. Сводка по воронке

| Мессенджер | Где настраивается автоответ | Что вставляем в текст | Может ли бот писать первым |
|---|---|---|---|
| Viber (профиль) | Automated Responses в приложении | `https://` + `viber://pa?chatURI=…` | нет (профиль ручной) |
| Viber (бот) | `conversation_started` welcome (код) | кнопки/URL/диплинк | только платно вне 24ч-сессии |
| Telegram | Telegram Business (нужен Premium) | `t.me/xxx_bot` | **никогда** (клиент жмёт Start) |
| WhatsApp (App) | Greeting/Away в приложении | `https://…` | нет |
| WhatsApp (Cloud API) | серверная логика | ссылка/кнопки/шаблон | только одобренным шаблоном |

## 3. Агрегатор мессенджеров (единый инбокс)

Задача: свести входящие из всех трёх каналов в один инбокс на портале, привязать переписку к карточке клиента по телефону и связать с конкретным ремонтом.

### 3.1. Архитектура

Общий принцип: у всех трёх платформ единая механика — **входящее приходит POST-ом на ваш webhook, ответ уходит POST-ом на их API с токеном.** Различаются только формат JSON, идентификаторы пользователя и правила «окна».

```
                    ┌──────────────────────────────────────┐
   Viber Bot API ──▶│  /viber/webhook                      │
   Telegram Bot  ──▶│  /telegram/webhook   (адаптеры)      │──▶ Нормализатор
   WhatsApp Cloud──▶│  /whatsapp/webhook                   │      сообщений
                    └──────────────────────────────────────┘         │
                                                                      ▼
                                              ┌───────────────────────────────────┐
                                              │  Единая модель Message/Conversation │
                                              │  привязка к Client по телефону      │
                                              │  привязка к Repair (ремонту)        │
                                              └───────────────────────────────────┘
                                                        │             │
                                                        ▼             ▼
                                                Единый инбокс     Исходящие
                                                на портале        (адаптер → API канала)
```

**Ключевые слои:**

1. **Адаптеры каналов (по одному на мессенджер).** Каждый принимает webhook, проверяет подпись, извлекает поля и приводит к единому виду:
   - Viber: подпись `X-Viber-Content-Signature` (HMAC-SHA256 тела токеном), пользователь = `sender.id`, ответ через `POST /pa/send_message`.
   - Telegram: проверка заголовка `X-Telegram-Bot-Api-Secret-Token`, пользователь = `chat_id`, ответ через `sendMessage`.
   - WhatsApp: подпись `X-Hub-Signature-256` (HMAC-SHA256 тела на App Secret), пользователь = `wa_id`, ответ на `POST /<PHONE_NUMBER_ID>/messages`.
2. **Нормализатор** — единый формат сообщения (см. модель данных), запись в БД, обновление состояния диалога, обновление «окна» (у Viber и WhatsApp — 24ч, у Telegram окна нет).
3. **Роутер/логика ответа** — либо ИИ-автоответ (переиспользуемый серверный endpoint для улучшения/генерации текста, по существующему в проекте паттерну AI-текстовых окон), либо ручной ответ оператора из инбокса.
4. **Единый инбокс на портале** — список диалогов, карточка клиента, история, связанный ремонт.
5. **Исходящий шлюз** — берёт нормализованный ответ и отдаёт в нужный адаптер с учётом ограничений окна (внутри окна — свободный текст; вне — шаблон WhatsApp / платное bot-initiated Viber; Telegram — без ограничений по времени).

### 3.2. Привязка к клиенту по телефону — важный нюанс

**Мессенджеры по умолчанию не отдают номер телефона клиента.** Идентификаторы разные и не равны телефону:

- Viber — `sender.id` (внутренний ID пользователя).
- Telegram — `chat_id` (по username/аккаунту, не по номеру).
- WhatsApp — `wa_id` (это номер в международном формате — **единственный канал, где телефон приходит сразу**).

Значит, автоматическая привязка «по телефону» надёжно работает только в WhatsApp. Для Viber и Telegram телефон нужно получить явно:

- попросить клиента прислать контакт/номер в начале диалога (в Telegram — кнопка «Поделиться контактом» `request_contact`; в Viber — сообщение типа `contact`);
- или связать через код: клиент приходит из личного кабинета/по ссылке с токеном привязки (`context`/`start`-параметр), и вы сопоставляете диалог с уже известным клиентом портала.

Модель хранения: одна сущность `Client` — много `ChannelIdentity` (по одной на канал). Это позволяет одному человеку писать из разных мессенджеров и попадать в одну карточку.

### 3.3. Модель данных (эскиз)

| Сущность | Ключевые поля | Назначение |
|---|---|---|
| `Client` | id, name, phone (нормализованный E.164), … | Карточка клиента портала |
| `ChannelIdentity` | id, client_id, channel (`viber`/`telegram`/`whatsapp`), external_id (`sender.id`/`chat_id`/`wa_id`), display_name, avatar | Привязка внешнего ID к клиенту |
| `Conversation` | id, client_id, channel, status, window_expires_at, linked_repair_id | Диалог; `window_expires_at` — таймер 24ч для Viber/WhatsApp |
| `Message` | id, conversation_id, direction (in/out), type (text/media/…), body, media_url, external_message_id, tracking_data, created_at | Нормализованное сообщение |
| `Repair` (существует) | id, client_id, status, … | Ремонт; связывается с Conversation |

Заметки к модели:
- `phone` храните в едином формате E.164 — иначе привязка WhatsApp `wa_id` к клиенту будет промахиваться.
- `window_expires_at` обновляется при каждом входящем от клиента (Viber/WhatsApp). У Telegram поле не используется (окна нет).
- `external_message_id` нужен для идемпотентности (webhook может прийти повторно) и для статусов доставки/прочтения.
- `linked_repair_id` — связь диалога с ремонтом; для одного клиента может быть несколько ремонтов, поэтому связь на уровне Conversation, а не Client.

### 3.4. Объём (что реально писать)

- 3 адаптера webhook (приём + проверка подписи + отправка) — самое трудоёмкое, но платформы близки по логике.
- 1 нормализатор + модель данных (5 сущностей выше).
- Логика «окна» для Viber/WhatsApp (24ч) и лимитов/бэкоффа (Telegram: ~1 msg/sec в чат, 429 → `retry_after`; Viber broadcast; WhatsApp tiers).
- UI единого инбокса на портале.
- Привязка телефона для Viber/Telegram (запрос контакта или код-связка).
- Идемпотентность и обработка статусов доставки/блокировок.

### 3.5. Риски

- **«Холодные» сообщения запрещены везде.** Проактивные уведомления («ваш кораблик готов») упираются в окна/шаблоны: Telegram — только если клиент уже нажал Start; Viber — вне 24ч платно (bot-initiated); WhatsApp — только одобренным шаблоном (платно). Нельзя строить воронку на исходящих в холодную.
- **Телефон приходит не всегда** (только WhatsApp даёт `wa_id`) — для Viber/Telegram нужен явный сбор номера, иначе привязка к клиенту/ремонту не автоматизируется.
- **Разные окна и лимиты** усложняют исходящий шлюз: 24ч у Viber/WhatsApp, отсутствие окна но rate-limits у Telegram, шаблоны и quality rating у WhatsApp.
- **Валидный SSL и проверка подписи обязательны** во всех трёх — просроченный сертификат = входящие тихо перестают приходить; без проверки подписи на открытый эндпоинт полетят поддельные запросы.
- **Онбординг WhatsApp долгий** (Business Verification 3–10 рабочих дней, возможны отказы по документам/адресу/имени) и Viber-бот — только через договор с партнёром (EUR 100/мес). Telegram запускается быстрее всего.
- **Блокировки и модерация:** клиент может заблокировать бота (обрабатывать `bot was blocked`/`failed`); массовые рассылки и спам ведут к снижению quality rating и бану.

### 4.2. Подводные камни (сгруппировано)

**Общие для всех:**
- Бот **не пишет первым в холодную** ни в одном из трёх — воронка только на входящем интересе (ссылка в автоответе / на сайте / в презентации).
- Обязателен валидный HTTPS и **проверка подписи** webhook (`X-Viber-Content-Signature` / `X-Telegram-Bot-Api-Secret-Token` / `X-Hub-Signature-256`).
- Токены — как пароли, только в env/Secret Manager (по политике проекта), не в коде.

**Viber:**
- Двоякость продукта — главная ловушка: webhook/токен/программная отправка есть **только** у платного бота; у бесплатного профиля автоматизация ограничена встроенными автоответами, входящие на ваш сервер не придут.
- Бота нельзя завести самому (с 05.02.2024) — только договор + EUR 100/мес.
- Окно 24ч: проактивное «ваш кораблик готов» вне сессии — платно.
- `viber://pa`-диплинки надёжны внутри Viber; во внешних браузерах дублируйте `https`.
- Номер владельца в бесплатном профиле клиентам не виден (плюс к приватности; звонки включаются отдельно).
- Точные тарифы для Украины и условия — у официального партнёра на этапе оформления.

**Telegram:**
- Бот работает по `chat_id`/username, **а не по номеру** — сообщения на личный номер владельца и боту это два разных канала; свести можно только через Telegram Business + подключение бота (нужен Premium).
- Rate limits: ~1 msg/sec в чат, ~30 msg/sec суммарно, до 20 msg/min в группу; при превышении 429 + `retry_after` — нужна очередь/бэкофф.
- Пользователь может заблокировать бота (`bot was blocked by the user`) — не считать доставленным.
- Один webhook-URL на токен; для dev/prod — разные боты/токены.
- Telegram Business даёт боту доступ к личной переписке владельца — ограничить видимые боту чаты (исключить контакты, только новые).

**WhatsApp:**
- Номер должен быть полностью чистым; после регистрации в Cloud API его нельзя параллельно использовать в обычном приложении.
- Первым — только одобренный шаблон; холодные рассылки без opt-in запрещены и ведут к бану.
- Модерация шаблонов (могут отклонить/переклассифицировать категорию, тогда меняется цена).
- Quality rating и tiers: старт с ограниченного лимита (обычно 250/1000 бизнес-инициированных диалогов в сутки), растёт при хорошем качестве; много жалоб → урезание/бан.
- Business Verification может затянуться (3–10 рабочих дней), частый отказ — из-за документов/адреса/имени.
- 24ч-окно легко «проспать»: ответ позже 24ч — только платный шаблон.

## 5. Рекомендованный порядок внедрения

**Этап 0. Подготовка (владелец, параллельно).**
- Собрать бренд-материалы (название, логотип, описание, часы, адрес, ссылки) — пригодятся во всех каналах.
- Выделить отдельный чистый номер под WhatsApp Cloud API и запустить Business Verification заранее (это самый долгий процесс).

**Этап 1. Telegram — первым (быстро, бесплатно, без верификаций).**
1. Создать бота через `@BotFather`, оформить (аватар/описание/команды), сохранить токен в Secret Manager.
2. Поднять `/telegram/webhook` (HTTPS + `secret_token`), реализовать приём и `sendMessage`.
3. Сделать нормализатор + модель данных (Client / ChannelIdentity / Conversation / Message / Repair) — этот слой переиспользуется остальными каналами.
4. Добавить сбор телефона (кнопка `request_contact`) и привязку к клиенту/ремонту.
5. Собрать первую версию единого инбокса на портале уже на одном канале.

**Этап 2. Viber — бесплатный профиль (A).**
1. Создать бизнес-профиль в приложении, заполнить, настроить welcome/away со ссылкой на сайт и (при желании) диплинк на будущего бота.
2. Использовать как «мостик» и ручной канал, пока не понадобится автоматизация.

**Этап 3. WhatsApp Cloud API (после прохождения верификации).**
1. Завершить Business Verification, зарегистрировать номер (`/register` + PIN), задать Display Name, создать System User и permanent token.
2. Поднять `/whatsapp/webhook` (GET-верификация `hub.challenge`, подписка на `messages`, проверка `X-Hub-Signature-256`).
3. Подключить адаптер к общему нормализатору; телефон берётся из `wa_id` автоматически.
4. Реализовать логику 24ч-окна и (при необходимости) 1–2 utility-шаблона для проактивных уведомлений.

**Этап 4. Viber-бот (B) — по потребности.**
- Оформлять платного бота (EUR 100/мес через партнёра) только когда действительно нужна серверная автоматизация входящих Viber на портал. До этого достаточно бесплатного профиля из Этапа 2.

**Этап 5. Автоматизация ответов (ИИ) поверх агрегатора.**
- Подключить серверный endpoint генерации/улучшения текста (по существующему в проекте паттерну AI-текстовых окон) к роутеру ответов.
- Соблюдать окна/шаблоны: свободный ИИ-текст — только внутри открытого окна (Viber/WhatsApp) или в любом Telegram-диалоге после Start.

**Логика приоритета:** сначала самый дешёвый и быстрый канал (Telegram) для отладки общего ядра агрегатора → бесплатный Viber-профиль как ручной мостик → WhatsApp Cloud API (долгая верификация, но `wa_id` даёт телефон сразу) → платный Viber-бот только по реальной необходимости.

## 6. Привязка к текущему коду RunFerry (важно)

Обобщённая модель из раздела 3 (`Client` / `ChannelIdentity` / `Conversation` / `Message`) в нашем проекте **не создаётся с нуля** — она ложится на то, что уже есть:

- `Conversation` + `Message` → уже существующий **`ChatSession` / `ChatMessage`** (`src/types/chat.ts`, `chatSessionService`). Добавляем на сессию поля `channel` (`'web' | 'viber' | 'telegram' | 'whatsapp'`) и `channelUserId` (внешний `sender.id` / `chat_id` / `wa_id`).
- `Client` → уже существующий **`ClientProfile`** (`src/api/clientProfileService.ts`), ключ = нормализованный телефон. WhatsApp `wa_id` — это и есть телефон → мгновенная привязка через `upsertByPhone`. Для Viber/Telegram телефон запрашиваем в диалоге (кнопка «поделиться контактом»), затем тот же `upsertByPhone`.
- `ChannelIdentity` → лёгкая коллекция-маппинг `channelIdentities/{channel}:{externalId}` → `{ phone, sessionId }`, чтобы повторные сообщения того же пользователя попадали в его сессию/профиль (для Telegram, где телефона нет сразу).
- Единый инбокс → расширяем существующий **`ManagerInboxPage`** фильтром по каналу + кнопкой «ответить» (сервер шлёт ответ обратно в адаптер канала).
- ИИ-ответы → переиспользуем готовые `/api/ai/estimate-chat` и `/api/ai/knowledge-chat`.
- Связь с ремонтом/задачами → уже есть (`serviceTask`, `/repair/new?chat=<id>`).

Итог: новый код — это **3 webhook-адаптера на сервере + исходящий шлюз + маппинг каналов + фильтр канала в инбоксе**. Ядро (диалоги, привязка по телефону, ИИ, ремонты) уже готово.
